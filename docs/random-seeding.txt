Playdate startup random seeding investigation — 2026-09-21

Finding

Explicit startup seeding was redundant for obtaining different initial sequences
in the tested macOS Simulator 3.1.2 (build 213590, SDK 3.1.2, Lua 5.4). Five
fresh processes without math.randomseed produced five distinct sequences. Five
with the current epoch-based seeding also produced five distinct sequences.
The fixed-seed control reproduced the same 12 integers in all five processes.

Whether the production call is redundant on physical Playdate remains uncertain.
No Playdate was available: system_profiler SPUSBDataType and /dev/cu.* listed
no Playdate; the USB serial device was a Flipper. No hardware runtime version
or hardware RNG sequence was measured. Do not extrapolate the Simulator result.

Decision on conditional removal

Craig authorized removal if testing establishes that the supported runtime
already supplies suitable varying startup seeds. The 15 fresh-launch samples
above establish this only for the Simulator; the hardware condition remains
unproven. A follow-up USB scan on 2026-09-21 again listed a Flipper and no
Playdate, so no physical-device sample could be collected.

Retain source/main.lua's seeding call under the task's explicit instruction to
keep it when necessity remains uncertain. Further Simulator launches would not
resolve the missing hardware evidence. Removal can be reconsidered when fresh
physical-device launches without the call establish suitable varying initial
sequences, with the hardware runtime version recorded.

Production seeding, SeededRandom.lua, and the date-seeded Daily maze path remain
unchanged. No tutorial anchors or generated listings need updating because the
production source is unchanged.

Method and reproduction

From the repository root, on macOS with the SDK installed:

    python3 tools/random-seeding/run.py --runs 5

For another SDK location, append --sdk /absolute/path/to/PlaydateSDK.
The runner compiles tools/random-seeding with that SDK's pdc --skip-unknown,
then invokes the Simulator executable directly, once per sample:

    "$PLAYDATE_SDK_PATH/bin/Playdate Simulator.app/Contents/MacOS/Playdate Simulator" \
      "$PWD/builds/random-seeding/RandomSeedDiagnostic.pdx" omitted

Use explicit or fixed instead of omitted to reproduce either control. Each
process exits on its third update; each subsequent process starts a fresh Lua
game runtime. These are not scene transitions, new-maze operations, resumes,
or repeated draws from a running game's RNG. The executable launch avoids
routing samples through an already-running Simulator instance.

The harness imports no game modules or CoreLibs. Before any other consumer,
it calls math.random(1, 1000000) exactly twelve times. The explicit arm captures
both returns of playdate.getSecondsSinceEpoch() and passes them to
math.randomseed(seconds, milliseconds), equivalent to the production nested
call. Lua passes both values in math.randomseed(playdate.getSecondsSinceEpoch()).
The fixed control uses math.randomseed(12345, 67890). The omitted arm never calls
math.randomseed. Modes alternate omitted/explicit/fixed over five rounds.

The diagnostic bundle ID is com.motlin.maze.random-seed-diagnostic; it does not
read or write datastore files or load Maze. All logs are console-only and the
host saves them beneath builds/random-seeding. No diagnostic logging is added
to production source, and the runner does not terminate another Simulator.

Official evidence and limits

https://sdk.play.date/3.1.2/Inside%20Playdate.html#f-getSecondsSinceEpoch
The installed SDK documentation and current official documentation describe the
epoch function's seconds and milliseconds results and give the production
seeding expression as an example. That demonstrates a supported way to seed;
it does not establish that explicit seeding is necessary or promise automatic
initialization. No Playdate runtime implementation evidence establishing the
startup seeding mechanism was found in the installed SDK/CoreLibs.

https://sdk.play.date/3.1.2/Inside%20Playdate.html#f-print
https://sdk.play.date/3.1.2/Inside%20Playdate.html#f-simulator.exit
The official API documents console output to stdout and the Simulator exit API
used to isolate and capture these launches.

Varying sequences support launch-dependent initial RNG state in this tested
Simulator, but do not identify the entropy source or prove variation across
all launches, OS versions, or hardware. Repeated sequences without seeding
would instead be evidence for retaining the explicit call for that runtime.
Desktop Lua defaults and SDK example prevalence were not used as proof.
